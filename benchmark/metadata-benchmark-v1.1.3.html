一、结论

  • 时间几乎全部花在元数据解析上，而不是遍历磁盘。目录遍历仅 108 ms（4.1%）， 逐文件读标签约 96%，建组仅 12–15 ms。
  • mutagen-rs 的逐文件接口确实更快，但只有 1.67×（端到端），不是数量级。 单文件解析 p50 从 0.208 ms 降到 0.100 ms（约 52%）。
  • 真正快 7–9× 的是 batch_open()，但它在本次实测中把标签配错到了别的文件上 （10,000 个文件里 8,685 个错位），属于不可用的“快”。
  • 加线程没有收益。tinytag 从 1 线程到 4/8 线程反而变慢（1933 → 2368 ms）， CPU 时间却涨到 3 倍，是典型的 GIL 争用；mutagen-rs 逐文件同样无收益。

五、关键发现：batch_open 的元数据错位

mutagen-rs 0.2.7 的 batch_open() 在批量较大时，返回的标签会对应到别的文件。 以本测试集为例：读取第 100 号文件的 TIT2，得到的是另一个文件的标题； 10 个文件时 0 错，100 个时 8 错，1,000 个时 528 错，10,000 个时 8,685 错。 重复运行两次结果完全一致（不是随机竞争），且返回的每个标题确实存在于库中其它文件 —— 是“配错对象”，不是解析错误。

另外用 200 个音源内容各不相同的文件复测（不同时长/码率），仍有 42 个（21%）错位，排除了“文件内容相同导致缓存串号”的解释。

同一批文件用逐文件接口 mutagen_rs.MP3(path) 读取时，10,000 条记录的 title/artist/album 与 tinytag 完全一致（0 差异）；tinytag 自身与 mutagen-rs 逐文件通道的交叉校验同样是 0 差异。 因此可以确认问题范围限定在 batch_open() 这一条并行批量通道上。

结论：不能用 batch_open() 的结果直接建组，否则界面会出现“张冠李戴”的标题与专辑。 若要用，必须在写缓存前逐条回读校验（那就抵消了它的性能优势），或等待上游修复。

六、时间构成分析

  • 目录遍历 108 ms：58 个目录 / 10,000 个目录项， 单次 os.scandir，已接近该磁盘与 CPU 的下限。
  • 元数据约 1933 ms（tinytag）/ 1568 ms（mutagen-rs）： 单个文件 0.1–0.2 ms，主要是 open + read + ID3 解析。CPU 时间分别为 1099 ms 与 715 ms， 其余是等待 I/O —— 即使换成 Rust 实现，单线程也无法绕开这部分等待。
  • 建组 12–15 ms：add_groups_from_scan() 只做字典归并与排序，已不是瓶颈。
  • 进度上报的代价：真实 ScanWorker（2613 ms） 比同口径流水线（2361 ms）慢约 251 ms， 主要来自约 1% 节流的跨线程 progress 信号与主线程事件处理。

七、建议

1. 短期：保留 tinytag，暂不替换

逐文件替换只能带来 1.67× 的端到端收益，却要引入一个需要为三端打包编译产物的 Rust 扩展 （本环境即由 sdist 现场编译）。在冷盘、大文件（数 MB）场景下，收益会被磁盘寻道进一步稀释。

2. 若确实要换：只用逐文件接口，不要用 batch_open

把 read_tinytag() 换成 mutagen_rs.MP3(p) 读取 TIT2/TPE1/TALB， 线程数保持 1（多线程无收益）。预期端到端约 1.67×，并需要在 CI 中为三大平台构建 wheel。

3. 真正的瓶颈在冷盘 I/O 与串行等待，换库解决不了

v1.1.3 文档记录的冷盘 2,379 文件约 44 s，主因是每个文件一次随机寻道。更有效的手段是 渐进式加载：扫描完成即按目录建组并显示，元数据在后台补齐； 再辅以惰性读取（只对当前可见/排序所需字段解析）。这能把“等待 44 秒才有界面”变成“秒级可见、逐步完善”。

九、局限

  • 仅热缓存：容器内 /proc/sys/vm/drop_caches 只读，无法构造冷盘场景；真实冷 HDD 下单文件耗时约高一个数量级，库间差距会被压缩。
  • 文件偏小：8.6 KiB/首，远小于真实 MP3（3–10 MiB）。真实场景中 I/O 占比更高，元数据解析占比更低。
  • 无内嵌封面：未包含 APIC（避免 10,000 张封面占数百 MiB）。含大封面时解析成本会上升，两个库的相对表现可能变化。
  • 未测内存：batch_open 一次性返回 10,000 条结果，峰值内存高于逐文件流式处理，本报告未量化。
  • 沙箱噪声：3 vCPU 共享环境，个别场景轮次间波动可达 ±15%（表中同时给出了最快值与中位数）。

十、复现

pip install "PySide6>=6.5.0" "tinytag>=1.8.0" just_playback==1.0.0 -i https://pypi.org/simple
pip install mutagen-rs -i https://pypi.org/simple

# 2) 生成测试集（10000 首，约 11 秒 / 97 MiB）
python benchmark/scripts/gen_mp3.py

# 3) 运行基准（输出 /tmp/bench_results.json）
python benchmark/scripts/bench_mp3.py
